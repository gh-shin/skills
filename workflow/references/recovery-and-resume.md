# 복구와 재개

지속 작업의 인계·재개, 기록 충돌, 외부 결과가 불확실한 실행의 복구에만 적용한다.
기존 기록을 활용하고, 작업에 필요한 상태와 근거만 남긴다.
스킬 지침만으로 외부 실행의 중복 방지나 재개 안전성이 보장되지는 않는다.
필요한 보장은 해당 도구의 기능과 운영 절차에서 확인한다.

## 기록과 실제 근거의 역할

목표·권한·진행을 판단할 기준 기록이 무엇인지 정하고, 기존 합의와 결정을 그 기록에 반영한다.
산출물은 현재 결과를, 검증 근거는 확인한 동작과 조건을, 외부 조회 결과는 실제 외부 상태를 보여준다.
상태 요약 자체는 코드·산출물의 동작이나 외부 실행 완료의 증거가 아니다.
같은 사실을 여러 곳에서 서로 독립적인 정본으로 관리하지 않는다. 필요한 곳에는 기준 기록이나 원근거의 위치를 연결한다.

기록과 실제 근거가 다르면 어느 쪽이 최신이며 어떤 주장을 뒷받침하는지 확인한다.
상태 차이를 요약에 맞춰 실제 결과를 덮어쓰는 방식으로 해소하지 않는다.
영향 받는 새 변경만 보류하고 읽기 전용 확인으로 현재 상태와 필요한 복구를 결정한다.
관련 없는 승인 작업은 계속할 수 있다.

## 지속 기록과 인계

필요에 맞게 기존 기록에 다음 상태를 남긴다. 모든 항목을 필수 필드로 만들지 않는다.

- 현재 목표·핵심 용어·필수 조건과 기존 권한
- 현재 작업, 완료·미검증·막힘 상태와 유효하지 않은 가정
- 현재 산출물에 적용되는 근거와 검증한 버전·조건
- 외부 확인 결과와 재실행하면 안 되는 행동
- 다음 행동, 필요한 입력 또는 결정 시점

중요한 산출물·검증·막힘·전제·결정·외부 확인 상태가 바뀌거나 인계·중단할 때 갱신한다.
특정 폴더, JSON 스키마, 모든 도구 호출의 기록을 요구하지 않는다.

인계받는 역할에 필요한 상태와 근거 위치를 먼저 전달한다.
전체 대화·로그는 필요한 부분만 추가한다. 인계 요약은 원기록이나 증거를 대체하지 않는다.
여러 에이전트가 같은 진행 기록을 갱신하면 누가 통합하는지, 최신 상태와 어떻게 대조하는지 분명히 한다.
이 목적만으로 별도 조정 담당자를 추가하지 않는다.

## 외부 결과가 불확실할 때

외부 효과가 있는 실행 전에는 결과 확인 방법과 사용 가능한 중복 방지 수단을 정한다.
timeout·응답 유실만으로 실패를 확정하지 않는다. 성공, 실패, 불확실 상태를 구분한다.

불확실한 실행은 다음 순서로 판단한다.

1. 실제 외부 상태, 실행 영수증, 조회 가능한 식별자 등 작업에 맞는 직접 근거를 확인한다.
2. 기록한 대상·입력·식별자와 대조해 실행 여부와 결과를 판단한다.
3. 이미 완료한 일은 재실행하지 않는다. 결과를 확인할 수 없으면 영향을 받는 새 변경을 보류하고 필요한 확인을 남긴다.
4. 미실행 또는 실패가 확인되고 재시도가 안전하며 기존 권한 안에 있을 때만 재시도한다. 도구가 중복 방지 key를 지원하면 같은 실행의 key를 재사용한다.

확인되지 않은 효과를 되돌리려 또 다른 외부 효과를 만들지 않는다.
복구·보상 전에 확인된 상태, 복구 범위, 위험, 기존 권한을 점검한다.
기존 승인이 유효하면 재사용하며, 복구에 필요한 권한이 없거나 범위가 달라질 때만 해당 결정을 확인한다.

## 과거 대화 없이 재개하는 시험

장기 작업, 중요한 인계, 기록 방식 변경 등에서 실제 가치가 있을 때만 재개 시험을 고려한다.
위임이 허용되고 도구가 있으면 새 에이전트에 과거 대화 없이 합의 기록·산출물·직접 인계·근거만 제공한다.
읽기 전용으로 다음 상태를 재구성하게 하고 원근거와 대조한다.

- 무엇이 완료되었고 무엇이 막혀 있는가?
- 어떤 전제가 폐기되었으며 무엇을 다시 하면 안 되는가?
- 다음 행동은 무엇이며 현재 목표·권한·근거에 부합하는가?

실제 외부 작업을 재실행해서 시험하지 않는다.
상태 복원과 다음 행동의 타당성을 관찰한 범위로 보고한다.
문서 존재만으로 재개 가능성이나 컨텍스트 압축 후 안전성을 보장했다고 주장하지 않는다.
필요한 도구가 없어 시험하지 못했으면 미검증으로 표시한다. 작은 작업마다 새 에이전트 시험을 요구하지 않는다.
