# 인터뷰 산출물과 체크 상태

인터뷰 결과를 기록하거나 합의가 바뀔 때 이 문서를 사용한다.
기존 작업 기록에 통합하고, 작업에 필요 없는 항목은 줄인다.
작고 명확한 작업은 대화 안의 짧은 체크리스트로 충분하다.
아래 틀은 작성 안내이며, 실제 답이나 근거 없이 합의 또는 완료로 체크하지 않는다.
인터뷰에서는 질문과 관련 정의를 하나씩 확인하고, 답변이 올 때마다 해당 항목을 갱신한다.
아래 틀 전체를 한꺼번에 답해야 하는 질문지로 제시하지 않는다.

## 체크 표시의 의미

| 구분 | `[ ]` | `[x]` |
| --- | --- | --- |
| 합의·결정 | 사용자 판단 또는 필요한 사실 확인이 남음 | 실제 사용자 답이나 확인 근거에 따라 결정됨 |
| 실행·검증 | 산출물 또는 완료 확인이 남음 | 관찰 가능한 결과를 얻고 지정한 방법으로 확인함 |

합의 항목의 체크는 실행 완료를 뜻하지 않는다.
실행 항목의 체크는 근거가 없는 동의나 계획 수립만으로 채우지 않는다.
실행·검증 목록에는 현재 합의한 범위의 항목을 넣는다.
아직 합의하지 않은 산출물이나 검증 방법은 제안·미결정으로 분리한다.
계획이나 문서를 작성하는 요청에 실제 운영·효과 측정을 완료 조건으로 자동 추가하지 않는다.
합의된 작업이 보류되거나 막혔으면 `[ ]`를 유지하고 이유를 적는다.
범위 밖 항목은 현재 작업의 완료 의무와 구분해 남긴다.
완료로 체크할 수 없는 항목을 숨기거나 필수 기준에서 임의로 삭제하지 않는다.

## 최소 Markdown 틀

아래 각 안내를 실제 작업 내용으로 바꾸고, 필요 없는 절은 생략한다.
실행 항목은 결과·확인법 또는 근거·목표 관계를 함께 기록한다.

```markdown
# 작업 합의와 진행 상태

## 목적과 기대 결과

- 목적: 사용자가 해결하려는 문제와 필요한 이유
- 기대 결과: 사용자가 받거나 관찰할 산출물·상태
- 범위와 제약: 포함·제외 대상, 지켜야 할 조건, 기존 권한

## 판단을 바꾸는 용어

| 용어 | 정의 | 해당 사례 | 반례·경계 사례와 판정 |
| --- | --- | --- | --- |
| 작업의 핵심 용어 | 이번 작업에서 쓰는 뜻 | 정의에 해당하는 구체적 상황 | 해당하지 않거나 추가 판단이 필요한 상황 |

## 성공·실패 기준

| 층위 | 성공 기준 | 실패 기준 | 확인 근거 |
| --- | --- | --- | --- |
| 프로젝트 | 기대 결과의 필수 조건 | 최종 결과를 수용할 수 없는 조건 | 실제 산출물·관찰·측정 |
| 단계 | 다음 진행에 필요한 결과 | 단계 목적을 달성하지 못한 조건 | 산출물 또는 결정 근거 |
| 시도 | 사전에 합의한 목표 결과 또는 학습 조건 | 합의한 허용 범위를 벗어난 조건 | 관찰·실험 결과와 다음 결정의 관계 |

## 주요 경로와 장애물

- 주요 단계와 의존성: 결과에 이르는 경로와 선행 조건
- 중요한 장애물·결정점: 영향, 선택지와 장단점

## 합의·결정 체크리스트

- [ ] 기대 결과와 필수 기준: 사용자 답 또는 확인 근거
- [ ] 핵심 용어와 사례 판정: 확인된 정의와 사례
- [ ] 중요한 선택: 결정 내용과 이유, 영향 받는 목표·계획

## 실행·검증 체크리스트

- [ ] 관찰 가능한 완료 결과 — 확인법·근거: 확인할 방법 — 목표 관계: 충족할 기준

## 미해결 사항과 다음 행동

| 사항·상태 | 결과에 미치는 영향 | 확인 방법 | 결정 시점·의존 작업 | 다음 행동 |
| --- | --- | --- | --- | --- |
| 미결정·보류·막힘·범위 밖과 이유 | 달라질 결과 또는 영향 없음 | 조사 또는 사용자 판단 | 의존 실행 전에 결정할 시점 | 독립적으로 진행할 일 또는 필요한 입력 |
```

## 갱신 규칙

알아낸 결정은 체크리스트뿐 아니라 관련 목표와 계획에도 반영한다.
조사 방법과 결정 시점이 합의되었어도 미결정 자체가 해결된 것으로 체크하지 않는다.
해결 방법에 대한 합의와 실제 해결 상태를 별도 항목으로 기록할 수 있다.

최종 승인된 기준은 유지한다. 변경 합의가 있으면 영향 받는 항목만 갱신하고 이유를 남긴다.
새 기준이 기존 완료 근거를 무효화하면 해당 실행·검증 상태를 다시 미완료로 바꾼다.
재개할 때 실제 산출물과 근거를 대조하고, 현재 상태에 유효한 체크만 유지한다.
